# auth-tasks — пример проекта для навыка `seditor`

A tiny demo project so you can verify the skill end to end. It has **two** roles:

1. `src/` is the *project the schemas describe* — a small auth + tasks app.
2. `SEditor/` is the *output* /seditor produces for it — generated **and verified** here,
   so you can see exactly what the skill is supposed to write.

## What's here

```text
auth-tasks/
├── README.md
├── package.json               # the demo "Auth + Tasks" app
├── src/
│   ├── auth.js                # register, login, 2FA, password reset
│   ├── tasks.js               # per-user CRUD
│   └── api.js                 # thin HTTP shim over both
└── SEditor/                  # ← generated by /seditor, safe to hand-edit
    ├── SEditor.html          # standalone editor copy: open it to edit any schema by hand
    ├── app/                   # managed SEditor runtime (editor.html + server.js + generator)
    ├── README.md              # how to open and validate the schemas
    ├── logic-auth-flow.json   # register → login → 2FA → token, + reset
    ├── designer-screen-map.json
    ├── data-model.json
    ├── code-module-map.json
    └── *.html                 # one launcher per schema (opens it with no server)
```

Files are named `<type>-<topic>`: the type prefix keeps names predictable, the topic keeps
two requests of the same type from overwriting each other.

## Look at the result

Double click any `SEditor/*.html` launcher — it opens the schema in the editor with no server.
The launcher carries the schema inside itself (`file://` cannot read a sibling JSON), so after an
agent edit to the JSON, regenerate the launcher:

```bash
node ../../skills/seditor/scripts/create-shortcut.mjs SEditor/logic-auth-flow.json SEditor/logic-auth-flow.html SEditor/app/editor.html
```

The optional backend (`node SEditor/app/server.js` from `auth-tasks/`) adds the recent-schema
list and direct disk writes.

That round trip is the whole point of the skill: **the agent writes JSON, the human edits it visually.**

## Reproduce it with the skill

In your agent of choice, from this folder, run any of these:

```text
/seditor map out the authentication flow including 2FA and password reset
/seditor describe all UI screens and the navigation between them
/seditor generate the data model and the module layout
```

The agent should produce the same shape of output that is already committed here.

## Validate

```bash
node ../../skills/seditor/scripts/validate-project.mjs .
```

Both must pass with exit code 0. The validator encodes the rules the bundled editor really
applies — including the non-obvious ones (positional zone/level/stage containment, size
clamping, the `"row,col"` table cell keys). Run it after hand-editing too.

To confirm the editor agrees, open a schema and check the browser console-free facts: the
node and edge counts should match the JSON, and no zone link should be dropped on save.
